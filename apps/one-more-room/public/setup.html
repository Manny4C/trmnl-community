# One More Room — TRMNL setup

New game built October 24, 2026. Website and installable source package are prepared. The owner Recipe is now created and installed as recorded above. Submission is verified; approval and physical receipt remain unconfirmed.

1. For the existing owner installation, continue Recipe **522318**; do not create another. New independent users can create a private plugin named **One More Room**. Use **Polling**, GET, framework **3.4.3 or later**. No headers, body, key or new paid service is required. Do not use Async Polling; it does not run the state transform.
2. Set its polling URL to the chapter-aware URL shown under Weekly chapter bridge below. A **15-minute refresh** is a reasonable starting point. The endpoint emits one token per minute; repeated fetches inside the same minute do not advance again. A plugin refresh is distinct from the device’s playlist cycle.
3. Copy `form-fields.yml` into Custom Fields. Save a seed and party instinct. A seed change starts a new campaign; instinct changes preserve the campaign.
4. In Edit Markup, put `shared.liquid` in Shared; copy the four matching `.liquid` layout files into Full, Half horizontal, Half vertical and Quadrant.
5. Select JavaScript on Serverless and paste the complete `transform.js`. It includes all game rules and reads `input.trmnl.state`; do not paste only the `run` function. The seed and instinct are read from `input.trmnl.plugin_settings.custom_fields_values`.
6. Save; Test/Force Refresh. The first fresh frame performs action 1. Later fresh frame tokens perform one additional action. Poll retries for the same token reuse the same turn. A long absence never simulates missed actions. Clear Saved State to restart with the same seed.
7. Use `icon.svg` for the plugin icon. Review native color/B&W in all four layouts and TRMNL X orientations before adding this separate plugin to your playlist. Keep all current playlist entries.

Full layout is split evenly: an illustrated atlas, recent journey, quest and party status on the left; ImageGen scene art and action choices on the right. The camera automatically shows the world at the start, entrances and keeper milestones, then focuses on the current dungeon and active encounter. The world chart shows six dungeon locations per chapter; dungeon paths derive from actual explored connections and the live party position. Labels and route overlays are generated from game state, not baked into the art. Half layouts compact the content; quadrant displays the map, scene and selected next action. Artwork is generated once during design and served from the companion site; no model calls occur on refresh. Scene art is an encounter-type illustration, not an exact newly generated depiction of each seeded enemy or room. Native images use the image-dither class; the website’s B&W control is an approximation. The action options are informational on the e-ink device. The Serverless function automatically chooses the highlighted action on the next update. The website’s choices are clickable and affect only its local campaign.

State is installation-specific and bounded. The transform has no network/model calls. Polling delivers a public minute token and chapter content; its URL includes only the public pinned chapter ID, never private campaign details. The map derives from seed/floor; party health, resources, cleared rooms and a rolling story log persist in Saved State. Browser history retains up to 120 actions; TRMNL retains six recent story events plus cumulative quest progress. Defeated parties lose half their gold, recover at the entrance and continue.

The platform has no reliable callback for every time a person sees a cached playlist image. A **fresh plugin update**, rather than every re-display of a stored frame, is the unit of play. An empty/failed poll leaves the previous journey intact. Same-token retries are idempotent; this does not claim transactional protection against two independently overlapping platform transforms.
